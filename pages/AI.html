阅读原文＋

核心原则：每次用户提出要求或给出任务后，必须先执行以下两步，缺一不可：

第一步：复述
用自己的话把用户的要求完整复述一遍，包括：
- 任务目标是什么
- 要改什么文件/做什么操作
- 预期的实现方式是什么
- 是否有任何约束条件（不改什么、保留什么）

第二步：确认
明确询问用户「是否符合你的预期？」或「是这个意思吗？」等确认语句

第三步：执行
只有在用户明确同意（说「是」「对」「可以」「去做吧」等肯定答复）后，才能开始执行任务。

违反后果：
- 擅自执行导致的方向错误、删错内容、改错逻辑 → 记入无效工作
- 老板已明确说「笨蛋」级别的不满时，需立即停止当前操作并请罪

代理规则 / 16

本地与云端项目同步规范

核心原则：本地与云端服务器上的项目必须通过Git版本管理同步，禁止在云端服务器上手动修改代码。 同步流程： 1. 在本地电脑修改代码…

阅读原文＋

核心原则：本地与云端服务器上的项目必须通过Git版本管理同步，禁止在云端服务器上手动修改代码。

同步流程：
1. 在本地电脑修改代码
2. 本地测试验证无误
3. 在本地执行 git add + git commit + git push 推送到远程仓库
4. 登录云服务器，执行 git pull 拉取最新代码
5. （如需要）npm run build 重新编译 + pm2 restart 重启

禁止行为：
❌ 直接在云服务器上用 vim/nano 等编辑器修改源代码
❌ 在云服务器上手动复制/粘贴文件到项目中
❌ 在云服务器上改动文件后不做 git 管理

例外情况：
- 配置文件（如 .env、nginx配置）不受此限制，可手动修改
- 临时调试排查可查看文件内容，但修改后必须用 git 覆盖回来

阅读原文＋

核心原则：接到涉及页面分析或网页抓取的任务时，必须优先使用 Crawl4AI 工具去抓取和分析页面，而不是用其他方式。

执行流程：
1. 收到任务
2. 判断是否涉及页面分析 / 网页抓取 → 是 → 进入第3步
3. 优先用 Crawl4AI：
- 抓取页面：crawl4ai 抓取 {URL}
- 分析页面：crawl4ai 分析 {URL}
- 结构化提取：crawl4ai query "要提取的内容" {URL}
4. Crawl4AI 结果不理想 → 再考虑其他抓取方式兜底

为什么优先用 Crawl4AI：
- 自动处理 JS 渲染、反爬、动态内容
- 输出结构化 Markdown，便于 AI 直接理解和分析
- 减少手工写爬虫脚本的麻烦和 token 消耗

适用范围：
- 分析网页内容、提取文章正文
- 抓取页面数据、结构化信息
- 需要理解某个网址页面内容的场景
