01 / 问题

库存、账单与财务数据散在多个平台，每月核算靠人工对账：30 分钟一次，还容易漏单错账。系统本身是黑盒，没有源码和文档，改不动，业务只能绕着系统走。

02 / 做法

用浏览器调试协议把散落在前端的业务规则、字段口径和接口能力逐条还原，重建前端工作台与核算后端，把核算拆成 9 个可执行步骤编排成一条流程；业务层与平台解耦，新平台只补适配器。

03 / 结果

核算从 30 分钟降到 3.5 分钟，一键出表且结果可复核；商品上架效率提升 10 倍以上；新增平台不再重写业务，一个人撑起整套系统的开发与迭代。

一个人负责跨境 ERP 的全栈开发：从黑盒系统还原、架构重构，到自动化财务核算与商品上架，把每月手工核算做成一键完成。

🏆 核心成就

10×+ 商品上架提效
8.6× 财务月结提效
1人 完成系统重建与迭代

🔍 阶段一：接手黑盒系统，还原业务全貌

  • 接手时没有源码、没有文档，也没有数据库权限；只能通过浏览器远程调试协议，把系统的业务规则、字段含义与接口能力一点点还原出来
  • 把散落在前端的业务逻辑整理成可交付的业务模型，重点吃透财务模块：每个字段的口径、来源与计算方式都与官方结果对齐
  • 输出结构化的接口与数据说明，让这套改不动的系统第一次有了可维护的依据
  • 解决 Service Worker 拦截、跨域 iframe、旧版认证方式等环境限制，形成一套可复用的接管方法
  • 结果：从只能照着旧系统操作，到能按业务需求改造

🎨 阶段二：重建一线工作台

  • 从零重建前端工作台：导航、菜单与操作路径按真实业务层级组织，日常经营的主要场景都能在同一套界面里完成
  • 商品、费用、结算与财务串在同一条操作链路里，减少在多个系统之间来回切换
  • 界面直接对接真实数据与业务接口，交付即可用，而不是只能看的原型
  • 结果：新界面成为财务与运营的日常工作入口，后续需求可以直接在系统内迭代

⚙️ 阶段三：把 30 分钟的手工核算，变成 3.5 分钟的一键核算

  • 打通登录鉴权与接口调用，把财务核算拆成 9 个可执行步骤，编排成一条可追踪的流程
  • 核算结果与官方数据逐字段对齐，字段映射经过多轮校准，导出的报表可直接用于对账与月结
  • 接口超时、空页与翻页异常都有自动重试与兜底，长时间核算不会中途断掉
  • 大结果集改为流式处理与流式导出，导出全量数据不再因内存占用而中断
  • 并发从串行改为流水线调度，同一台机器就能稳定跑完整个核算流程
  • 结果：单次核算 30 分钟 → 3.5 分钟，且可重复、可复核

🏗️ 阶段四：让系统能长出下一个平台

  • 把业务逻辑与平台差异拆开：路由层 → 通用业务层 → 平台适配层，业务层不再写平台判断
  • 新增一个平台只需补一个适配器，不用重写业务代码
  • 核算、成本查询等能力独立成模块，接入新平台或调整口径都不影响主流程
  • 每一步都可独立执行、可并行、进度可追踪，出问题能定位到具体环节
  • 结果：新增平台从“重做一遍”变成“补一个适配器”

🤖 商品自动化上架系统

  • 设计四层协作的系统：ERP 底座承接库存，商品中枢统一商品与定价，采集服务补齐平台数据，发布端完成多平台上架，覆盖库存聚合 → 标准商品库 → AI 处理 → 自动上架全链路
  • TikTok 三路径协同：内部接口逆向（Cookie 鉴权）+ CDP 浏览器反检测自动化（Patchright）+ 官方 Partner API 调研路线，突破无文档平台的集成壁垒
  • 支撑 TikTok Shop / Shopee / Amazon / Temu 等 多平台自动上架，新增平台只需补一个适配器
  • AI 全链路参与：LLM 自动生成商品标题、类目与卖点描述，并自动应用平台的商品优化建议
  • 封装 Tauri 桌面客户端（WebView2 + 内置 Node Sidecar），运营人员安装即用，支持 Sidecar 级热更新
  • 数据库分层：SQL Server 承接标准商品库，SQLite 承载执行端任务队列，Docker 容器化部署

🛡️ 工程保障

  • 用户权限系统：三级角色体系（超管/管理员/商家）+ JWT认证 + 安全加固
  • 数据库自动初始化：幂等建表 + 自动迁移 + 种子数据
  • Token自动刷新中间件：内存缓存 + 过期预刷新 + 透明调用
  • 操作日志系统：关键操作留有日志，支持按条件追溯
  • 云服务器部署：PM2 进程管理 + Nginx 反代 + SSL + 0 停机更新
  • 架构评审：识别出的改进项逐项落地，剩余短板统一排期

🐛 复杂Bug排查案例

  • 数据不一致：架构重构后每次导出结果都不同 → 定位到多处接口调用缺少重试、异常被静默吞掉 → 统一修复后结果稳定
  • 隐式 Bug：结算日期全部为空，字段映射却完全正确 → 根因是迁移时日期窗口参数变了，症状与根因毫无关联 → 修正后恢复
  • 分页数据丢失：偶尔少一批订单 → 发现接口偶发返回空页却仍给了翻页 token → 加入同 token 重试后不再丢单
