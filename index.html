🔍 阶段一：存量系统逆向分析

  • 无源码、无API文档、无数据库访问权限，仅通过浏览器远程调试协议（CDP）对存量系统进行全面扫描
  • 批量提取 850个JS文件源码（~150MB），从中反推出 359个API路径 和完整数据模型
  • 覆盖 17个业务模块、约450个功能页面 的结构分析，重点对财务模块完成深层字段级分析
  • 攻克 Service Worker 拦截、跨域 iframe、ASP.NET AJAX 认证等6项技术难点
  • 开发完整的逆向分析工具链（批量扫描、深层分析、源码下载、报告生成、Cookie注入）

🎨 阶段二：前端SPA系统重建

  • 完成技术选型评估：React 18 + TypeScript + Ant Design 5 + Vite 6 + Zustand
  • 搭建完整SPA容器架构：19个业务模块导航、~500条菜单路由、多列悬浮菜单、标签页拖拽排序
  • 手写开发 20个真实业务功能页面（含完整交互逻辑和数据展示）
  • 建立前端三层架构（API数据层 + Zustand状态层 + 业务视图层），Vite build编译通过（3156 modules）

⚙️ 阶段三：后端搭建与API对接

  • Express + TypeScript 模块化分层架构，包含签名算法、认证授权、数据库持久化、进度追踪等完整基础设施
  • 手工阅读 296个API接口文档，整理为结构化文档 + Apifox可导入格式
  • 实现完整OAuth 2.0流程，攻克签名算法3个关键陷阱
  • 财务数据字段映射历经 3个版本迭代，逐字段验证确保导出结果与官方数据完全一致
  • 一键核算功能：9步编排，~7000次API调用，单次核算约3.5分钟（优化前30分钟）
  • 并发优化：Promise.all → 滑动窗口 → 流水线模式，CPU利用率从低到持续满载
  • 内存优化：全量缓存 → JSONL流式临时存储 + 流式Excel写入，驻堆内存降低75%~96%
  • 双层超时保护 + 指数退避重试 + 同token翻页重试，保障API调用稳定性

🏗️ 阶段四：多平台架构重构

  • 设计 三层解耦架构：路由层 → 通用业务层 → 平台适配层，业务层零平台判断分支
  • 实现 Platform Adapter模式 + 工厂注册机制，新增平台只需1个Adapter类 + 1行注册代码
  • 定义跨平台标准化类型体系，作为业务层与适配层的契约
  • Workflow编排模式：每步独立可执行、可并行、进度可追踪
  • CostProvider独立拆分，解耦成本查询与平台业务逻辑

🤖 商品自动化上架系统（Vue/.NET/Node/Python）

  • 设计四层微服务架构：.NET ERP底座 + Node.js商品中枢 + Python爬虫服务 + Node.js多平台发布端，覆盖库存聚合→标准商品库→AI处理→自动上架全链路

  • 支撑 TikTok Shop / Shopee / Amazon / Temu等 多平台自动上架，新增平台仅需实现 Adapter 两个核心方法
  • AI全链路赋能：LLM 自动生成商品标题/类目/图片，自动化应用 TikTok 商品优化工具建议

🐛 复杂Bug排查案例

  • 数据不一致：架构重构后每次导出结果不同 → 发现10处API调用缺重试、catch块静默吞异常 → 一次性修复
  • 隐式Bug：结算日期全部为空，字段映射正确 → 根因是迁移时日期窗口参数变更（±30天→原始日期）→ 症状与根因毫无关联
  • 分页数据丢失：偶尔少一批订单 → 发现API偶发返回空页但仍给翻页token → 实现同token重试机制

AI模型路由网关

独立开发

自研的多模型智能路由中间件，实现AI CLI工具与多厂商大模型之间的请求代理、负载均衡与故障切换。

  • 设计模型路由层：支持 多厂商模型动态切换，请求自动转发至可用模型
  • 实现故障自动降级：主模型不可用时秒级切换至备用模型，保障服务连续性
  • 协议兼容层：完整实现OpenAI Chat Completions API协议，AI客户端（Codex CLI等）零改造接入，将请求透明转发至DeepSeek、通义千问等国产模型
  • 模型路由引擎：基于配置的Provider注册机制，每个Provider声明模型ID、端点、认证方式；路由层根据请求中的model字段匹配Provider，动态构建目标请求
  • 故障降级策略：主Provider返回5xx/超时后，自动将请求重试至备用Provider，支持配置重试次数与超时阈值，降级过程对客户端完全透明
  • 流式响应透传：完整支持SSE（Server-Sent Events）流式输出，逐token转发模型响应，保持客户端打字机效果
  • Token中转架构：通过第三方API网关统一管理多厂商API Key，网关侧做鉴权与限流，本服务仅持有网关凭证
Node.js TypeScript Express REST API SSE
