# 六类后台系统的界面参考与差异化设计结论（2026-10）

> 调研口径：每个类目列出 12 个可公开访问的产品站 / 演示环境，从**布局、多级导航、配色与主色、状态色、按钮与输入、图标、弹窗与抽屉、业务流程**八个维度做拆解。
> 说明：以下分析基于产品官网、公开 Demo、帮助文档与官方截图；未逐像素核对线上版本，具体数值（圆角、字号）是"读图估计 + 同类产品共识"，落地时请以自己产品的令牌为准。
> 目的不是"抄一个"，而是**给六类系统各找一套不同的骨架**——现在六类的排版太像，问题不在配色，在于它们的**核心对象与主操作**本来不同，却用了同一种"左侧菜单 + 顶部 KPI + 表格"的模板。

## 0. 先定结论：六类系统的差异矩阵

| 类目 | 核心对象 | 主操作 | 导航骨架 | 主色 | 密度 | 特色组件 |
|---|---|---|---|---|---|---|
| ERP 进销存 | 单据（PO/SO/入库单） | 批量处理 + 单据流转 | 图标栏 + 模块内二级菜单 + 单据详情抽屉 | 工业蓝 `#2563EB` | 高（行高 36–40） | 单据状态链、批量条、行内编辑 |
| CRM 销售 | 客户/商机 + 活动 | 推进阶段 + 记跟进 | 视图式导航（保存的视图）+ 看板 | 紫 `#7C3AED` | 中（44） | 阶段看板、活动时间线、下一动作 |
| SOP 流程 | 流程实例 + 检查项 | 执行步骤 + 留痕 | 目录树（流程库）+ 实例工作区 | 青绿 `#0D9488` | 低（48–56，偏阅读） | 步骤条、检查清单、运行日志、证据附件 |
| BI 分析 | 指标 + 时间 | 筛选 + 下钻 + 订阅 | 深色顶栏 + 全局筛选条 + 图表面板 | 深空蓝 + 亮青 `#22D3EE` | 中低（图表留白） | KPI 带目标、下钻面包屑、阈值告警 |
| OA 审批 | 表单 + 审批节点 | 提交 / 通过 / 驳回 / 加签 | 工作台 + 待办队列 + 表单/流程双栏 | 靛 `#4F46E5` | 中（44） | 审批链可视化、会签/或签、意见模板 |
| 财务费控 | 票据 + 金额 + 合规 | 采集 → 校验 → 支付 → 记账 | 左侧账套/期间 + 票据工作台 + 右侧汇总 | 墨绿 `#047857` | 高（行高 36） | 票据匹配、差异处理、多币种折算 |

**通用状态色（六类共用一套语义，不要再各写一套）**

| 语义 | 色值 | 用法 |
|---|---|---|
| success | `#16A34A` | 已通过 / 已入库 / 已匹配 / 目标达成 |
| warning | `#D97706` | 待复核 / 观察期 / 接近阈值 |
| danger | `#DC2626` | 已驳回 / 缺件 / 超阈值 / 差异 |
| info | `#0284C7` | 处理中 / 在途 / 同步中 |
| neutral | `#64748B` | 草稿 / 停用 / 归档 |

> 红线：**状态不要只靠颜色**。每处都配图标或文案（✓ / ! / ▲），否则色盲用户与打印场景直接失效。

## 1. ERP / 进销存

### 1.1 业务流程（与其它五类的分界）

```
请购 → 采购订单 → 到货收货 → 质检入库 → 应付对账 → 付款 → 成本结转
        │            │          │
        └ 变更/取消   └ 差异处理  └ 退货
```

- **特征**：以"单据"为原子，任何操作都会产生一条新单据或改变单据状态；用户 80% 时间在列表里找单、改单、批量处理。
- **UI 推论**：列表必须支持**多选 + 批量**、**行内快捷操作**、**单据详情抽屉**；不需要 CRM 那种时间线，也不需要 BI 那种图表墙。

### 1.2 12 个参考

**1. Odoo** · odoo.com
- 布局：应用宫格首页 → 模块内切换"列表 / 看板 / 图表 / 日历"；KPI 用低饱和底色块分组（蓝/橙/琥珀），不是高饱和实心块。
- 导航：顶栏统一放搜索 + 筛选 facet + 记录数 + 视图切换，一行解决。
- 色彩：主色随模块变化但饱和度克制；标签与状态用柔色 chip。
- 组件：金额右对齐等宽数字；状态 chip 带圆点；表单长字段折叠分区。
- 借鉴：**KPI 用 5–8% 底色分区**，比整块填色高级得多。

**2. ERPNext** · erpnext.com
- 布局：首页当"启动器"，主体是分域链接（Reports & Masters），只放一张 P&L 图。
- 导航：左侧一级域 → 列表页用筛选器；面包屑清晰。
- 色彩：白底 + 灰边，几乎不用主色铺面积。
- 组件：数字卡片只显示"数量 + 标签"，不放无意义的环比。
- 借鉴：**ERP 首页不必是仪表盘**，可以是指引页；没有意义的 delta 不要硬加。

**3. Oracle NetSuite（Redwood UI）** · netsuite.com
- 布局：粘性头部常驻搜索与「Create New」；长表单按分区折叠；筛选从页面底部移到列表顶部。
- 导航：全局导航 + 最近访问 + 收藏，减少层级跳转。
- 色彩：中性灰白为底，主色只用于主按钮与选中。
- 组件：大点击区域、表格行 hover 出快捷操作（Redwood 的典型做法）。
- 借鉴：**"新建"要常驻**——ERP 用户最高频动作就是建单。

**4. SAP S/4HANA Fiori** · sap.com/fiori
- 布局：语义化 tile 工作台（概览型 / 分析型 / 列表型 / 对象型四种 floorplan）。
- 导航：按业务角色组织，而非按模块。
- 色彩：Fiori 蓝为主，状态色严格分级。
- 组件：Object Page（对象页）——头部摘要 + 分区 + 相关单据。
- 借鉴：**按角色给工作台**，销售看到的是报价与交期，仓管看到的是待收货。

**5. Microsoft Dynamics 365 Business Central** · dynamics.microsoft.com
- 布局：列表 + 右侧 FactBox（关键信息常驻）；单据页顶部 Ribbon。
- 导航：与 Office 一致的顶部 Ribbon + 左侧导航。
- 色彩：Office 蓝，克制。
- 组件：FactBox 是 ERP 里非常值得抄的结构——列表右边永远有一块"这笔单的关键数字"。
- 借鉴：**列表 + 右侧事实框**，比"点进去看详情"快得多。

**6. Katana MRP** · katanamrp.com
- 布局：制造/库存双视图，卡片式库存状态，产能用条形占用图。
- 导航：左侧模块 + 顶部搜索。
- 色彩：白底，主色偏蓝紫，状态用色块。
- 组件：库存卡直接显示"可用 / 已分配 / 在途"三段。
- 借鉴：库存数**拆成三段**展示，比一个总数有用。

**7. Cin7 Core** · cin7.com
- 布局：密集订单表 + 右侧滑出详情；顶部筛选器。
- 导航：左侧模块 + 二级菜单。
- 色彩：蓝灰，专业感。
- 组件：订单状态用带序号的状态条（Pending → Picked → Packed → Shipped）。
- 借鉴：**状态链**比单个状态徽标更能表达"走到哪了"。

**8. MRPeasy** · mrpeasy.com
- 布局：制造排程甘特 + 物料清单（BOM）树。
- 导航：左侧模块，二级用标签页。
- 色彩：浅底 + 蓝主色。
- 组件：甘特条带"延期红 / 今天橙"的阈值编码。
- 借鉴：时间轴类视图要用**颜色阈值**而不是统一色。

**9. Infor** · infor.com
- 布局：行业化工作台，偏工业风的深色顶栏 + 浅色内容。
- 导航：全局 + 行业模块。
- 色彩：深蓝 + 高对比，适合车间大屏。
- 组件：大字号数字与状态墙。
- 借鉴：车间/仓库场景要考虑**远距离可读**，字号与对比度要上一个档。

**10. 金蝶云·星空** · kingdee.com
- 布局：新版工作台可配置"常用功能 / 待办事项 / 异常播报"三区。
- 导航：模块 + 工作台方案切换。
- 色彩：扁平灰白 + 蓝色主色，数据大屏另有一套深色。
- 组件：异常播报区（逾期订单、待处理收料）直接给出待办入口。
- 借鉴：**异常优先**——把"出问题的地方"放在工作台首屏。

**11. 用友 YonSuite** · yonyou.com
- 布局：角色工作台，卡片可拖拽重组。
- 导航：按角色预置桌面 + 模块菜单。
- 色彩：企业蓝 + 卡片式。
- 组件：可配置卡片（无代码拖拽）。
- 借鉴：工作台**可配置**，但默认要给一套"开箱即用"的布局。

**12. 聚水潭** · jushuitan.com
- 布局：电商 ERP 的订单/仓储看板，密集表格 + 状态筛选条。
- 导航：左侧一级 + 顶部二级标签。
- 色彩：蓝白为主，促销/异常用红橙。
- 组件：批量打单、批量发货的操作条。
- 借鉴：**批量操作条常驻在表格上方**，选中即生效，比悬浮工具条稳。

### 1.3 ERP 设计结论

| 项 | 建议 |
|---|---|
| 主色 | `#2563EB`（工业蓝）；hover `#1D4ED8`；浅底 `#EFF6FF` |
| 状态 | 待复核 `#D97706`、已入库 `#16A34A`、已驳回 `#DC2626`、在途 `#0284C7` |
| 导航 | 52px 图标栏（一级）+ 212px 模块菜单（二级）+ 单据详情右侧抽屉 |
| 列表 | 行高 38–40；首列复选；金额右对齐等宽；行 hover 出「编辑 / 复制 / 打印」icon |
| 特色 | 单据状态链（4 段）、批量条、右侧事实框、异常播报卡 |
| 弹窗 | 建单用**宽表单抽屉**（600px），不要用小 modal 塞 12 个字段 |

**我们现在的差距**：ERP 页面用的是"KPI + 表格 + 弹窗"，缺状态链、缺右侧事实框、缺批量条的常驻感。

## 2. CRM / 销售

### 2.1 业务流程

```
线索 → 资格确认 → 商机 → 报价 → 谈判 → 赢单/丢单 → 交付转接
        │           │                    │
        └ 培育池     └ 阶段停留超时告警     └ 输单原因必填
```

- **特征**：以"人 / 商机"为原子，价值在**阶段推进**与**跟进记录**；用户要回答"这单现在什么状态、下一步做什么"。
- **UI 推论**：看板 + 活动时间线是主角，表格是辅助；列表要能按"保存的视图"切换。

### 2.2 12 个参考

**1. Attio** · attio.com
- 布局：表格优先（类 Notion），单元格类型有独立视觉（文本/数字/日期/单选/关联）；记录页把"关系"做成可点击的实体。
- 导航：**以保存的视图为导航**（如"本月将成交""30 天未联系"），不是文件夹树。
- 色彩：克制到近乎黑白 + 单点强调色。
- 组件：行内编辑、列头排序筛选、AI 摘要作为"设计过的组件"而不是聊天气泡。
- 借鉴：**视图即导航**；表格要"快"，不要每改一个字段就弹窗。

**2. Pipedrive** · pipedrive.com
- 布局：管道看板为主视图，列头带金额与单数；卡片上直接显示"逾期活动"红色信号。
- 导航：左侧模块 + 顶部管道切换。
- 色彩：深绿主色，阶段用不同色带。
- 组件：**行内新增**（直接在列里加商机 / 记一通电话），不跳页。
- 借鉴：录入走"最小可用字段"，细节后补——这是 CRM 转化率的关键。

**3. HubSpot** · hubspot.com
- 布局：多产品套件，顶部按"市场/销售/服务/运营"分区，二级再分视图。
- 导航：全局顶部导航 + 二级侧栏。
- 色彩：橙色品牌色，但内容区大面积中性。
- 组件：记录页左侧属性、右侧活动流。
- 借鉴：**按 job-to-be-done 组织一级导航**，不按功能模块。

**4. Salesforce Lightning** · salesforce.com
- 布局：App Launcher + 记录页 Highlights Panel（关键字段置顶）+ Related Lists。
- 导航：App 切换器 + 对象标签页。
- 色彩：蓝，密度高，可配置性强。
- 组件：路径组件（Path）——把阶段做成带引导的进度条。
- 借鉴：**Path 组件**是 CRM 阶段推进最好的视觉表达。

**5. folk** · folk.app
- 布局：极简表格 + 左侧分组，详情用侧边浮层（不占满屏）。
- 导航：分组列表。
- 色彩：几乎无彩色，靠排版建立层次。
- 组件：侧边 popover 详情。
- 借鉴：**轻量 CRM 用浮层看详情**，保持列表上下文。

**6. Close** · close.com
- 布局：活动优先（通话/邮件/短信量），排行榜其次。
- 导航：左侧模块 + 内置拨号器。
- 色彩：深色侧栏 + 浅色内容。
- 组件：一键呼叫 / 邮件序列直接嵌在列表行里。
- 借鉴：**输入型指标（打了多少电话）要看板化**，不只盯结果。

**7. Twenty** · twenty.com
- 布局：开源 CRM，Notion 式表格 + 看板 + 干净的记录页。
- 导航：左侧工作区 + 对象。
- 色彩：中性灰 + 单主色。
- 组件：表格/看板切换器，字段类型可视化。
- 借鉴：可直接读源码学习表格与看板的实现（AGPL，注意协议）。

**8. Copper** · copper.com
- 布局：深度嵌在 Gmail/Workspace 里，记录页与邮件打通。
- 导航：侧栏 + Google 生态入口。
- 色彩：暖棕/铜色，亲和。
- 组件：邮件侧栏卡片。
- 借鉴：**和日常工作流（邮箱）绑定**，减少"再去一个系统"的成本。

**9. Zoho CRM** · zoho.com/crm
- 布局：KPI 卡片每个数字都配"目标 + 趋势"。
- 导航：模块 + 视图。
- 色彩：多色但克制，图表用统一色板。
- 组件：目标进度环。
- 借鉴：**数字必须有参照**（目标/上期），孤立数字没有决策价值。

**10. monday CRM** · monday.com
- 布局：widget board（看板可拼装仪表盘）。
- 导航：工作区 + 视图。
- 色彩：色彩饱和、明快（刻意的差异化）。
- 组件：拖拽拼装 widget。
- 借鉴：允许用户**自建视图**，但默认给一套成品。

**11. 销售易** · xiaoshouyi.com
- 布局：国内大型 CRM，列表 + 详情 + 审批流打通。
- 导航：模块 + 二级菜单。
- 色彩：蓝主色，状态色规范。
- 组件：客户 360 视图、商机阶段推进器。
- 借鉴：**客户 360** 把散落在各模块的信息聚合到一屏。

**12. 纷享销客** · fxiao.com
- 布局：连接型 CRM，销售/服务/渠道一体。
- 导航：应用中心 + 模块。
- 色彩：蓝绿，偏移动端友好。
- 组件：移动端卡片式跟进记录。
- 借鉴：**移动端优先的跟进录入**（语音转文字、拍照上传）。

### 2.3 CRM 设计结论

| 项 | 建议 |
|---|---|
| 主色 | `#7C3AED`（紫，区别于 ERP 的蓝）；阶段色带用同色系明度阶 |
| 状态 | 热线索 `#DC2626`、跟进中 `#D97706`、赢单 `#16A34A`、丢单 `#64748B` |
| 导航 | 左侧"视图"列表（我的管道 / 本月将成交 / 30 天未联系）+ 顶部视图切换（看板 / 列表） |
| 主视图 | 看板（列头带金额与单数）+ 卡片只放三件事：客户、金额、下一步 |
| 特色 | Path 阶段条、活动时间线、行内新增、客户 360、逾期高亮 |
| 弹窗 | 记跟进用**右侧浮层**（保持看板可见），新建商机用居中 modal |

**我们现在的差距**：CRM 只有看板和表格，没有 Path、没有活动时间线、没有"下一动作"字段。

## 3. SOP / 流程与知识库

### 3.1 业务流程

```
模板设计 → 发布（版本） → 生成实例 → 逐步执行 → 检查项勾选 → 异常分支 → 归档留痕
              │                          │
              └ 变更需审批并通知          └ 附件/截图作为证据
```

- **特征**：以"流程实例"为原子，价值在**不漏步**与**可追溯**；用户执行时要"当前该做什么、做完留下什么"。
- **UI 推论**：步骤条 + 检查清单 + 日志三件套；阅读密度低、字号可大；不需要密集表格。

### 3.2 12 个参考

**1. Process Street** · processstreet.com
- 布局：实例工作区左侧步骤列表、中间当前步骤表单、右侧备注/附件。
- 导航：工作流库 → 运行实例。
- 色彩：蓝紫，状态用勾选进度表达。
- 组件：条件分支（if this then that）、任务分配、审计轨迹。
- 借鉴：**步骤即页面**，一次只让用户面对一步。

**2. Trainual** · trainual.com
- 布局：Subject → Topic → Step 三层内容树，阅读式排版。
- 导航：左侧目录树 + 进度。
- 色彩：亮色、友好，弱化"系统感"。
- 组件：章节测试、完成勾选、角色分配。
- 借鉴：**学习型 SOP** 要有测验与完成度，不只是文档。

**3. Scribe** · scribehow.com
- 布局：自动截图 + 编号步骤，一条一图。
- 导航：文档库。
- 色彩：白底 + 品牌色点缀。
- 组件：自动捕获、敏感信息模糊、可嵌入。

## 4. BI / 经营分析

### 4.1 业务流程

```
数据接入 → 建模（指标定义） → 看板搭建 → 发布/订阅 → 下钻分析 → 告警 → 归因
```

- **特征**：以"指标"为原子，价值在**可信**与**可下钻**；用户先看"哪里不对"，再问"为什么"。
- **UI 推论**：全局筛选（时间/维度）+ 指标卡（带目标与对比）+ 图表（少装饰）+ 下钻路径；深色模式是常见诉求（监控场景）。

### 4.2 12 个参考

**1. Grafana** · grafana.com
- 布局：统计行（大数字）→ 图表 → 明细表，最耐用的仪表盘结构。
- 导航：左侧折叠菜单 + 仪表盘列表。
- 色彩：近黑底 + 灰字，**饱和色只出现在数据上**。
- 组件：时间范围选择器（含相对时间）、告警规则、变量筛选。
- 借鉴：**"只有数据可以有颜色"**——这是深色看板不显廉价的关键。

**2. Kibana** · elastic.co/kibana
- 布局：可折叠分区（告警/日志/主机），每区带"查看全部"。
- 导航：侧栏几十项（反面教材：层级过深）。
- 色彩：浅色为主，可切深色。
- 组件：表格行内嵌 sparkline（不额外占一块图表位）。
- 借鉴：**行内迷你趋势图**能在不增加高度的情况下表达趋势。

**3. Metabase** · metabase.com
- 布局：问题（Question）→ 看板；卡片式查询结果。
- 导航：集合 + 收藏。
- 色彩：白底 + 蓝，图表色板克制。
- 组件：可视化查询构建器、下钻（点柱状图看明细）、订阅与告警。
- 借鉴：**每个图表都能点进去看明细**，这是 BI 的信任来源。

**4. Apache Superset** · superset.apache.org
- 布局：仪表盘网格 + 图表库。
- 导航：数据集 / 图表 / 仪表盘。
- 色彩：可换主题，默认浅色。
- 组件：SQL Lab、仪表盘过滤器联动。
- 借鉴：**过滤器联动**（选区域，所有图一起变）是分析效率的关键。

**5. Looker Studio** · looker.google.com
- 布局：自由画布 + 报表分页（执行摘要 / 渠道 / 漏斗 / 受众）。
- 导航：报表列表。
- 色彩：白 + 品牌色，模板化。
- 组件：scorecard、日期控件、下钻维度。
- 借鉴：**分页叙事**——第 1 页给结论，后面给细节。

**6. Tableau** · tableau.com
- 布局：工作表 / 仪表盘 / 故事三层次。
- 导航：工作簿 + 数据源。
- 色彩：中性 + 分类色板。
- 组件：参数、集、计算字段。
- 借鉴：**"故事"这种串讲结构**适合向上汇报。

**7. Power BI** · powerbi.microsoft.com
- 布局：报表页 + 切片器 + 交叉筛选。
- 导航：工作区 + 报表。
- 色彩：黄主色，图表主题可定制。
- 组件：DAX 度量、钻取、书签。
- 借鉴：**书签**能保存"某个筛选视角"，便于分享。

**8. Sigma** · sigmacomputing.com
- 布局：电子表格式 BI（单元格即图表）。
- 导航：工作簿。
- 色彩：白 + 蓝。
- 组件：百万行级表格、公式。
- 借鉴：**表格与图表同源**，分析师不用在两套心智间切换。

**9. Rill** · rilldata.com
- 布局：极简看板，指标优先，图表带单位与口径说明。
- 导航：项目 / 看板。
- 色彩：克制，功能色为主。
- 组件：时间对比、维度下钻。

**10. 帆软 FineBI** · fanruan.com

- 导航：目录 + 我的分析。
- 色彩：蓝，支持大屏深色主题。

**11. 观远数据** · guandata.com

- 导航：主题域 + 看板。

**12. 网易有数** · youdata.netease.com
- 布局：拖拽式看板 + 大屏。
- 导航：项目空间。
- 色彩：深色大屏模板丰富。
- 组件：大屏组件库、轮播。

### 4.3 BI 设计结论

| 项 | 建议 |
|---|---|
| 主色 | 深色模式：底 `#0B1220`、卡 `#131C2E`、数据亮青 `#22D3EE`；浅色模式主色 `#0284C7` |
| 状态 | 达标 `#16A34A`、预警 `#D97706`、超阈值 `#DC2626`、中性 `#64748B` |
| 导航 | 顶部深色条（品牌 + 时间范围 + 全局筛选）+ 左侧看板目录 |
| 主视图 | 指标行（含目标/环比）→ 趋势图 → 构成图 → 明细表 |
| 特色 | 口径说明、下钻面包屑、行内 sparkline、订阅、告警阈值线 |
| 图表 | 去网格线、去边框、每条线一个语义；分类色 ≤5 |

**我们现在的差距**：BI 页还是浅色 + "KPI 四宫格 + 两个图"，没有全局筛选、没有下钻、没有口径说明。

## 5. HR / OA 审批

### 5.1 业务流程

```
发起（表单） → 条件分支 → 审批节点（或签/会签/加签） → 抄送 → 归档 → 数据回流（考勤/薪资/预算）

- **特征**：以"表单 + 流程"为原子，价值在**规则可配**与**状态透明**；发起人要"填得快"，审批人要"看得懂、批得快"。
- **UI 推论**：表单与流程并置；待办用队列；审批链可视化（谁批了、谁在等、等了多久）。

## 6. 财务 / 费控

### 6.1 业务流程

```
消费/发票采集 → OCR 识别 → 验真查重 → 预算与政策校验 → 审批 → 支付 → 记账 → 归档
                                    │

- **特征**：以"票据 + 金额"为原子，价值在**合规**与**对得上**；任何数字都要能追溯到凭证。
- **UI 推论**：票据工作台（左列表 + 右明细/影像）+ 差异突出 + 多币种折算 + 汇总卡。

### 6.3 财务设计结论

| 项 | 建议 |
|---|---|
| 主色 | `#047857`（墨绿，资金/稳妥）；差异与超支用红 |
| 状态 | 已匹配 `#16A34A`、待确认 `#D97706`、差异/缺件 `#DC2626`、已归档 `#64748B` |
| 导航 | 期间/账套选择器 + 票据工作台 + 右侧汇总 |
| 主视图 | 左：票据列表（含币种图标）；右：本币折算汇总 + 差异项 + 操作 |
| 特色 | 匹配状态、差异金额（带正负号）、多币种、批次支付、凭证追溯 |
| 数字 | 金额一律等宽 tabular-nums；整数与小数分档；负数带 `-` 号不只靠颜色 |

**我们现在的差距**：财务页有票据和汇总，但缺"匹配/差异/缺件"三态队列与凭证追溯。

## 7. 落地建议（针对现有六类应用）

现在的六个 app 共用同一套骨架（顶栏 + 左侧菜单 + KPI + 表格），所以"长得像"。建议按上表逐类改造，优先级从高到低：

1. **换主色 + 换主视图**（收益最大、成本最低）
   - ERP 保持蓝、主视图=密集表 + 右侧事实框；CRM 改紫 + 看板；SOP 改青绿 + 三栏步骤；BI 改深色 + 筛选条；OA 改靛 + 表单/审批双栏；财务改墨绿 + 票据工作台。
2. **补每类的"特色组件"**（决定专业度）
   - ERP：单据状态链、批量条常驻、异常播报
   - CRM：Path 阶段条、活动时间线、下一动作字段
   - SOP：版本徽标、检查项、审计日志、证据附件
   - BI：全局筛选、下钻面包屑、指标口径、阈值线
   - OA：审批链等待时长、会签/或签、意见模板
   - 财务：匹配三态、差异金额、多币种折算、凭证追溯
3. **弹窗形态差异化**
   - ERP 建单 → 宽抽屉；CRM 记跟进 → 右侧浮层；SOP 异常 → 确认弹层；BI 订阅 → 小 modal；OA 驳回 → 必须填原因的弹层；财务 差异 → 分栏弹层（左凭证右调整）。
4. **导航形态差异化**
   - ERP 图标栏 + 模块菜单；CRM 视图列表；SOP 目录树；BI 看板目录 + 顶部筛选；OA 工作台 + 模板库；财务 期间选择 + 任务队列。
5. **统一令牌**（避免各写一套）
   - 六类共用：字号阶 11/12/13/14/16/20/28、行高 40/34、圆角 6/8/10、间距 4pt、语义状态四色、焦点环 2px、动效 120/180/240ms。
   - 只有"主色 + 密度 + 主视图 + 特色组件"按类变化。
